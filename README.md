# شبکه‌سنج (NetCheck)

ابزار رایگان، متن‌باز و فارسی برای اجرای تست‌های واقعی شبکه از نقاط مختلف
جهان، با تمرکز ویژه بر ایران.

این پروژه از API عمومی [Globalping](https://globalping.io) استفاده می‌کند
و هیچ داده‌ای را به‌صورت جعلی یا شبیه‌سازی‌شده نمایش نمی‌دهد. هر نتیجه‌ای
که می‌بینید از یک اندازه‌گیری واقعی روی یک پروب واقعی به دست آمده است.

> **توجه**: این پروژه به‌صورت مستقل توسعه یافته و هیچ وابستگی تجاری با
> Globalping ندارد. ما از API عمومی آن‌ها تحت سهمیهٔ ناشناس استفاده
> می‌کنیم.

## ویژگی‌های فعال

هر ویژگی زیر به یک اندازه‌گیری واقعی روی API عمومی Globalping متصل است:

| نوع تست        | روش واقعی                                       | توضیح |
| -------------- | ----------------------------------------------- | ----- |
| **Ping**       | `POST /v1/measurements` با `type=ping`          | تأخیر، از دست رفتن بسته و IP حل‌شدهٔ مقصد از پروب واقعی. |
| **TCP Port**   | `type=traceroute` با `protocol=TCP` و `port`   | Traceroute با TCP SYN روی پورت مقصد. این روش **مسیر TCP** را تا پورت مقصد بررسی می‌کند و رسیدن به مقصد نشان‌دهندهٔ باز بودن پاسخ‌دهی TCP به آن پورت است. |
| **UDP Port**   | `type=traceroute` با `protocol=UDP` و `port`    | مسیر UDP به پورت مقصد. UDP بدون اتصال است؛ نبود پاسخ **دلیلی بر بسته بودن پورت نیست**. این تست نمی‌تواند قطعاً باز/بسته بودن را اثبات کند. |
| **DNS**        | `type=dns` با `query.type` و `protocol`         | پرس‌وجوی DNS از پروب واقعی با ۱۶ نوع رکورد پشتیبانی‌شده. |
| **HTTP/HTTPS** | `type=http` با `protocol` و `request.method`   | درخواست HTTP واقعی از پروب با نمایش کد وضعیت، تأخیر، TLS و خطاهای شبکه. |

ویژگی‌های UI:

- رابط کاربری کاملاً فارسی و راست‌چین (RTL)
- پشتیبانی از پوستهٔ روشن/تیره/سیستمی
- انتخاب موقعیت پروب از ۱۹۰+ کشور با فیلتر دقیق بر اساس شهر یا ASN
- **ایران به‌صورت پیش‌فرض و در صدر فهرست** موقعیت‌ها
- تأیید هویت پروب ایرانی در نتیجه (اگر ایران درخواست شده باشد)
- کپی JSON و دانلود فایل نتیجه
- مدیریت خطا، rate-limit، timeout و حالت‌های ناشناخته
- رابط واکنش‌گرا برای موبایل، تبلت و دسکتاپ
- احترام به `prefers-reduced-motion`

## محدودیت‌های فنی

### محدودیت تست TCP

Globalping در حال حاضر نوع اندازه‌گیری مستقلی برای «بررسی پورت TCP» ندارد.
ما از `traceroute` با `protocol=TCP` و `port=<port>` استفاده می‌کنیم. این
روش:

- اگر مقصد روی پورت TCP پاسخ‌دهی نشان دهد (مثلاً SYN-ACK)، مسیر تا مقصد
  تکمیل می‌شود و IP مقصد در آخرین گام ظاهر می‌شود. این **نشانه‌ای از
  پاسخ‌دهی TCP روی آن پورت است**.
- اگر مقصد پاسخ ندهد، ممکن است پورت بسته، فیلتر شده، یا unreachable باشد.
  نبود پاسخ **دلیلی قطعی بر بسته بودن نیست**.

در رابط کاربری، حالت‌های «اتصال برقرار شد»، «بدون پاسخ قطعی از مقصد»،
«بدون پاسخ» و «خطا» به‌صورت مجزا نمایش داده می‌شوند.

### محدودیت تست UDP

UDP یک پروتکل بدون اتصال است. ما از `traceroute` با `protocol=UDP` و
`port=<port>` استفاده می‌کنیم. این تست **مسیر شبکه تا مقصد روی پورت UDP
مشخص** را اندازه می‌گیرد اما **نمی‌تواند باز یا بسته بودن پورت را به‌طور
قطعی اثبات کند**. در رابط کاربری این موضوع به‌صورت صریح اعلام شده است.

### سهمیهٔ ناشناس Globalping

Globalping به هر آدرس IP ناشناس یک سهمیهٔ محدود اختصاص می‌دهد. در زمان
توسعه این پروژه، سرآیند `x-ratelimit-limit` برابر با `250` بود. این عدد
ممکن است در آینده تغییر کند — مقادیر واقعی همیشه از سرآیندهای پاسخ خوانده
می‌شوند و در صورت برخورد با rate-limit، پیام فارسی مناسب نمایش داده
می‌شود.

برای اجرای تست‌های بیشتر می‌توانید یک توکن شخصی از
[globalping.io](https://globalping.io) دریافت کنید و آن را در متغیر محیطی
`GLOBALPING_API_TOKEN` قرار دهید (این توکن هرگز به مرورگر ارسال نمی‌شود).

| 206065  | Tose'h Fanavari Ertebabat Pasargad Arian      | eyeball         |
| 48551   | Sindad Network Technology                     | datacenter      |

این فهرست ثابت نیست — پروب‌های جدید به‌صورت خودکار شناسایی می‌شوند و
پروب‌های آفلاین از فهرست حذف می‌شوند.

**مهم**: وجود یک پروب در ایران به‌معنای پوشش همهٔ ISPها یا دیتاسنترهای
ایرانی نیست. ما فقط داده‌های واقعی را نمایش می‌دهیم و هیچ پوشش nationwide
را بدون مدرک موثق ادعا نمی‌کنیم.

## پیش‌نیازها

- Node.js نسخهٔ ۲۰ یا بالاتر (توصیه‌شده: ۲۲ LTS)
- npm یا bun یا pnpm
- اتصال اینترنت برای دسترسی به API عمومی Globalping

## نصب و اجرای محلی

```bash
# نصب وابستگی‌ها
npm install

# اجرای سرور توسعه‌ای
npm run dev
# سپس به http://localhost:3000 بروید
```

اگر از متغیرهای محیطی اختیاری استفاده می‌کنید:

```bash
cp .env.example .env.local
# سپس مقادیر مورد نظر را در .env.local ویرایش کنید
```

## اجرای تست‌ها

این پروژه از [Vitest](https://vitest.dev) برای تست‌های واحد استفاده
می‌کند. تست‌ها شامل بررسی اسکیماهای اعتبارسنجی، منطق تفسیر نتیجه و
رفتار کش هستند.

```bash
npm run test
```

تست‌های مرورگری با Playwright را می‌توان با دستور زیر اجرا کرد (نیازمند
نصب باینری مرورگر):

```bash
npx playwright install
npm run test:e2e
```

## استقرار روی Vercel

این پروژه برای استقرار روی Vercel بهینه‌سازی شده است:

1. مخزن را به Vercel push کنید یا از CLI آن استفاده کنید:

   ```bash
   npm i -g vercel
   vercel
   ```

2. در صورت نیاز به متغیرهای محیطی، آن‌ها را در پنل Vercel اضافه کنید
   (اختیاری — بدون هیچ متغیری هم کار می‌کند).

3. Vercel به‌صورت خودکار `next build` را اجرا کرده و خروجی را روی Edge /
   Node قرار می‌دهد. هیچ تنظیم اضافی لازم نیست.

نکته‌ها:

- Route handlerها روی Node.js runtime اجرا می‌شوند (`runtime = "nodejs"`).
- فهرست پروب‌ها در کش درون‌فرآیندی (in-memory) نگهداری می‌شود. در محیط
  Serverless، هر instance جداگانه کش خود را دارد — این رفتار قابل قبول است
  زیرا Globalping همان فهرست را برای همه برمی‌گرداند و فقط یک کش اضافی
  بار شبکه ایجاد می‌کند.
- هیچ پایگاه داده یا ذخیره‌سازی دائمی لازم نیست.

## استقرار روی Cloudflare (اختیاری)

استقرار روی Cloudflare Pages/Workers به‌دلیل محدودیت‌های runtime و چرخهٔ
حیات serverless ممکن است نیاز به تنظیمات اضافی داشته باشد. در حال حاضر
تنها **Vercel** به‌عنوان هدف اصلی پشتیبانی می‌شود. اجرای روی Cloudflare
نیازمند بررسی جداگانه است و در این نسخه به‌صورت آزمایشی پشتیبانی نمی‌شود.

## رفع اشکال

### «هیچ پروبی در دسترس نیست»

سرور Globalping ممکن است موقتاً در دسترس نباشد یا شبکه شما به آن دسترسی
نداشته باشد. چند لحظه صبر کنید و دکمهٔ «به‌روزرسانی» را در انتخابگر
موقعیت بزنید.

### «Rate limit»

سهمیهٔ ناشناس شما تمام شده است. زمان بازنشانی در پیام نمایش داده می‌شود.
می‌توانید یک توکن شخصی از globalping.io بگیرید و در `GLOBALPING_API_TOKEN`
قرار دهید.

### «موقعیت ایران انتخاب شد اما هیچ پروب ایرانی در این نتیجه شرکت نکرد»

این حالت زمانی رخ می‌دهد که پروب‌های ایرانی موقتاً آفلاین شده باشند یا در
آن لحظه کدام در دسترس نباشد. شبکه‌سنج به‌جای استفاده از پروب کشور دیگر،
صراحتاً اعلام می‌کند که نتیجه از داخل ایران نیست.

### «اتصال برقرار نشد» برای TCP/UDP

این پیام به‌معنای عدم پاسخ مقصد است، نه اثبات بسته بودن پورت. فایروال،
فیلترینگ یا timeout می‌توانند دلیل باشند.

### خطای TypeScript یا ESLint در زمان توسعه

```bash
npx tsc --noEmit
npm run lint
```

اگر خطا از وابستگی‌های شخص ثالث است، `node_modules` را پاک و دوباره نصب
کنید:

```bash
rm -rf node_modules
npm install
```

## هشدار حریم خصوصی

**مقصد و پارامترهای تست شما ممکن است توسط سرویس Globalping ثبت یا
نمایش‌داده شود.** این سرویس ممکن است لاگ‌های خود را برای رفع سوءاستفاده
نگه دارد. از وارد کردن موارد زیر خودداری کنید:

- آدرس‌های IP داخلی یا محرمانه
- توکن‌ها، رمزها یا کلیدهای API
- آدرس‌های دامنهٔ داخلی شرکت‌ها
- هر اطلاعاتی که نباید در محیط عمومی ثبت شود

شبکه‌سنج هیچ داده‌ای را به‌صورت دائمی ذخیره نمی‌کند و هیچ تحلیلی روی
مقاصد شما انجام نمی‌دهد. تمام نتایج فقط در حافظهٔ مرورگر نگهداری می‌شوند
و پس از بستن صفحه از بین می‌روند.
